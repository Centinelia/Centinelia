## Qué se agregó

- **Scope `spreadsheets`** al OAuth de Google. Los orgs conectados antes del despliegue deben reconectar para autorizarlo.
- **Tabla `sheets_mappings`** (por `portal_email`, por propósito): `clientes | leads | bitacoras | oc | cajas_chicas | custom`.
- **Servicio `src/lib/services/sheets.ts`**: `getMapping`, `refreshHeaders`, `appendRow`, `updateRow`, `readRange`, `searchInTab`, `hasAnyMapping`, `syncLeadToSheets`.
- **4 tools nuevas** en los 3 canales (voz + chat + oficina):
  - `sheets_agregar_fila` (capability `sheets.write`, requires_approval por default)
  - `sheets_actualizar_fila` (capability `sheets.write`, requires_approval)
  - `sheets_leer` (capability `sheets.read`, allow por default)
  - `sheets_buscar` (capability `sheets.read`, allow por default)
- **Sync opcional** de `crear_lead` → hoja de leads, activable por agente vía `voice_agents.sync_leads_to_sheets`. Fire-and-forget: nunca bloquea el flujo, loggea fallas en `agent_learnings`.
- **5 endpoints portal** para CRUD de mappings + listar spreadsheets/tabs + refresh headers, todos con IDOR + rate limit.
- **UI portal:**
  - IntegrationsHub: nueva tarjeta unificada `GoogleWorkspaceCard` para Gmail + Drive + Sheets + Calendar + Contacts.
  - Configurar → sección "Sheets del negocio" para conectar sheets por propósito, refrescar columnas, activar sync automático de leads.

## Migración

Aplicada en Supabase dev el 2026-08-04. Prod pendiente antes del piloto.

```sql
-- supabase/migrations/20260804_sheets_mappings.sql
CREATE TABLE sheets_mappings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  portal_email TEXT NOT NULL REFERENCES organizations(portal_email) ON DELETE CASCADE,
  purpose TEXT NOT NULL CHECK (purpose IN ('clientes','leads','bitacoras','oc','cajas_chicas','custom')),
  custom_purpose_label TEXT,
  spreadsheet_id TEXT NOT NULL,
  tab_name TEXT NOT NULL,
  headers JSONB NOT NULL DEFAULT '[]'::jsonb,
  headers_synced_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK ((purpose = 'custom' AND custom_purpose_label IS NOT NULL) OR (purpose != 'custom' AND custom_purpose_label IS NULL))
);
CREATE UNIQUE INDEX sheets_mappings_pe_purpose_reserved ON sheets_mappings (portal_email, purpose) WHERE purpose != 'custom';
CREATE UNIQUE INDEX sheets_mappings_pe_custom_label ON sheets_mappings (portal_email, custom_purpose_label) WHERE purpose = 'custom';
CREATE INDEX sheets_mappings_portal_email ON sheets_mappings (portal_email);
ALTER TABLE voice_agents ADD COLUMN sync_leads_to_sheets BOOLEAN NOT NULL DEFAULT false;
-- + set_updated_at() trigger
```

## Limitaciones conocidas

- `updateRow` solo soporta sheets con ≤26 columnas (A-Z). Extender a AA-ZZ cuando surja una hoja real que lo requiera.
- El scope check runtime (`scope_missing`) NO está enforced porque `integration_accounts` no tiene columna `scopes`. La única enforcement es al momento de OAuth grant. Si un usuario no reconecta después de este deploy, las tools recibirán 403 de la Sheets API al ejecutarse (loggeado a nivel de tool).
- Headers de sheet son case-sensitive contra las keys del payload. `sync_leads_to_sheets` fires con keys lowercase (nombre, telefono, email, notas, fuente, fecha). Los headers del sheet de leads deben coincidir; de lo contrario se dispara `headers_mismatch` y se loggea sin bloquear el flujo.
